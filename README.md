# dsh-studio（dsh工作室）

把**会话提升为成员**（别名 / 颜色标签 / 角色 / 能力标签 / 锁定 / 置顶），并在此基础上做**跨会话群聊**
（手动 `queue` 传话 + 双向消息回流）的 DSH 插件。

一句话原则：**只加"关于会话的元数据"和"一条 user 消息"，绝不改写任何会话的内容。**
不重写历史、不压缩、不改标题/模型/权限/工作目录、不抢占进行中的 turn。

---

| S2 | **锁定**：锁定成员禁止归档（宿主层权威 + 客户端层可见提示） | ✅ |

## 为什么"锁定"是必要的

DSH 当前版本**没有删除会话的能力**（客户端 RPC 面里 `sessions` 没有 delete）。
唯一让会话从侧边栏消失的动作是**「归档会话」**，而 `archivedSessionIds` 是一个**只增不减**的集合，
全仓库找不到任何 unarchive / restore 代码路径 —— 也就是**一键不可逆**。

所以：成员**默认锁定**；被锁定的会话尝试归档时会被拒绝（宿主层权威拦截），
面板还会弹一条提示说明原因。要在面板里解锁后才能归档。

## 安装

```bash
# 1) 把本包链接进 web profile 的 node_modules（改源码即生效；npm 升级不会覆盖）
#    把 <本包所在目录> 换成你 clone/放置本包的**绝对路径**

# Windows（cmd / PowerShell）
cmd /c mklink /J "%USERPROFILE%\.dsh\profiles\web\node_modules\dsh-studio" "<本包所在目录>"

# macOS / Linux
ln -sfn "<本包所在目录>" "$HOME/.dsh/profiles/web/node_modules/dsh-studio"
```

> 用**链接**而不是 `npm install`：这样改本包源码是**即刻生效**的，且 DSH 自身升级不会把它覆盖掉。
> 也可以直接把本包复制进那个目录，但那样每次改源码都要重新复制一遍。

```yaml
# 2) 追加到 $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: studio
      name: dsh-studio
```

3) **刷新页面**（boot manifest 是页面加载时注入的，新插件不会自己出现在已打开的窗口里）。

### 回滚

```powershell
# ① 删掉 cordis.patch.yml 里 dsh-studio BEGIN/END 之间的整段
# ② cmd /c rmdir "%USERPROFILE%\.dsh\profiles\web\node_modules\dsh-studio"
```

## 使用

- 左边缘的「工作室」把手，或侧边栏底部的「工作室」开关 → 拉起左侧抽屉。
- **面板不覆盖会话列表**：打开时面板停在侧边栏**右侧**、并让中间对话列右移同样的宽度，
  等于在主框架里"占了一格"（主框架只有三列 + 一个浮层且 `details` 已被产品占用，没有第四列可注册，
  所以是用"让出空间"实现，见「已知限制」）。
- **成员台**：搜索会话 → 「提升」（默认锁定）→ 编辑别名/颜色/角色/能力；「已锁/未锁」切换锁定；「置顶」把成员排到最前。
  另有两个侧边栏呈现开关：「侧边栏置顶」与「成员行标记」。
- **侧边栏里的成员会话**（自动，无需操作）：
  - 会话行**淡灰底 + 自己颜色的圆点**；
  - 在所属工作区分组内**置顶**（工作区表头之下、普通会话之上），并与普通会话之间有一条分隔线；
  - 颜色来自成员台里选的颜色标签（8 色板）。
- **群聊**：选一个成员作为投递目标 → 输入 → 「发送」。成员选择与输入框**都固定在面板下方**（中间是时间线）。
  - 投递模式固定 `queue`（= 宿主侧 `agent.followup()`，**排队不抢占对端进行中的工作**）。
  - 对端是冷会话会被自动 resume（带着它自己的上下文干活），它的回复自动出现在时间线上。
  - 「读该成员最近 50 条」用产品自己的分页 history 接口做**只读**回填。
  - 「显示/隐藏系统注入」：`Current runtime context.` / `<system-reminder>` / 后台子代理汇报这类
    非对话内容默认隐藏（数据仍记录）。
- 消息在对方日志里的样子（前缀让对端模型能看清归属与类型）：
  ```
  【群聊·我的工作室｜say｜来自 我】
  正文…
  ```

## 给 agent 的群聊接口

> 面向成员 agent 的独立说明（可直接发给其他会话）：**`AGENT-GUIDE.md`**（同目录）。

成员之间的对话有两条通路，**语义完全一样**（都是 `mode:"queue"` → 宿主侧 `agent.followup()`，排队不抢占）：

### ① 命令行（**立刻可用**，推荐先用这条）

```powershell
# 列出成员
node bin/say.mjs --list

# 给某个成员发一条（发送者身份自动取 $DSH_SESSION_ID，所以它在哪个会话里跑就是谁发的）
node bin/say.mjs --to "教练成员" --kind ask --text "请帮我修 05-数据结构 那批编译不过的模板"

# 只看构造结果、不真的发（自检用）
node bin/say.mjs --to "站点成员" --text "..." --dry-run
```

- 任何会话里的 agent 都可以直接这样调用（它本来就有 shell 工具），**不需要先注册什么工具**。
- `--kind` 可选 `say`（默认）/ `ask`（委托）/ `deliver`（交付）/ `share`（共享）。
- 消息会以 `【群聊·<群名>｜<类型>｜来自 <发送者>】` 开头进入对方会话；对方的回复回到**你的**会话。
- `--inbox` 查"谁给我发过、我回过没有"，判定有四种：`✅ 已回执（ack/decline/deliver）` /
  `⚠️ 欠回执：…` / `⚠️ 之后我没回过` / `⚪ 无法判定（…别据此重发）`；人类在面板里直接转达的消息标为 `（非成员）`，不计入判定。
  「回没回」按**同一发送者**算（给 A 回过不会把 B 的旧消息也标成已回）。
- `--version` 打印版本号 + 文件时间 + 能力清单；报 bug 或怀疑"跑的是旧版"时先跑它。
- `--to "@all"` 发给全体，**不含你自己**；PowerShell 里必须加引号（否则被当数组语法吃掉）。

#### ①a 寻址规则（2026-10-08 强化，起因是一次**真实的误投**）

解析按**层级**取最优，层级小的赢；**并列最优不猜**（返回"有歧义"并列出候选，而不是取第一个）：

| 层级 | 匹配方式 | 例 |
|---|---|---|
| 0 | 别名精确（不区分大小写） | `--to 维护者` |
| 1 | 完整会话 id | `--to session-11111111-…` |
| 2 | 短 id（8 位） | `--to 11111111` |
| 3 | 别名**前缀** | `--to 旧` |
| 4 | 别名**子串** | `--to 维护` |

- **退役记录在 3/4 两级 +10 降级**：交接后新旧同名（`维护者` / `旧[2026-10-08]维护者`）时，
  简称 `维护` **必须**落到接任者、不能落到已退役的旧会话（旧实现取"第一个子串命中"⇒ 是否误投**取决于成员表顺序**）。
- **退役判据**（`protocol.isRetired`）：别名带退役前缀 `旧[…` / `旧·` 等，**或** `locked === false`（本产品里"锁定"＝禁止归档 ⇒ 解锁记录＝随时可归档的旧记录）。
- **精确命中不受降级影响**：写全名或短 id 永远能点到那条记录，包括退役的那条。
- **旧写法容错**：`维护者(旧)` / `维护者（旧）` 只在**退役记录**里解析（否则会被"别名精确"这一级判给接任者）。
- 回归测试：`node test/resolve.test.mjs`（27 项，含**正对照**——照抄旧实现证明它确实会误投，否则用例是空的）。
- ⚠️ **生效范围**：本规则在 **CLI（`bin/say.mjs`）立刻生效**；`studio_say` 原生工具在**宿主半边**，需**下次重启主星**才拿到。

### ①c 发送前的三道闸门（CLI 本地判断，**不需要重启**）

一次**消息风暴**事故（当时单小时到达量远超服务能力、广播占了很大比例）之后加的三道闸门。
关键认识：那天的消息**没有一条是重复的、也没有一条是无理的** —— 每条都正当、都不同，
可到达量（12~17 条/10 分钟）是服务能力（2~5 回合/10 分钟）的 3~6 倍。
**这种过载只能靠"停一段时间"止血，不能靠"每条发得更慢"。**

| # | 闸门 | 拦什么 | 代价 |
|---|---|---|---|
| ① | **暂停** | 指定时段内一条都不发（可只点名几个成员） | `--pause-status` 查看；到点自动失效 |
| ② | **限流** | 同目标 60 秒内重复 / 本人 60 秒内 ≥6 条 / 10 分钟内二次广播 | 被拦时打印**是哪一条** |
| ③ | **定向自检** | 首行写「`【你 → 某人】`」却发给了别人 | **只告警，不阻断**（广播里点名某人是合法写法） |

```powershell
node bin/say.mjs --pause-status                    # 只读，暂停期照样能用
node bin/say.mjs --pause 60 --reason "风暴止血"      # 暂停 60 分钟（缺省=全体）
node bin/say.mjs --unpause
```

- **只拦"发"，不拦"看"**：`--inbox` / `--list` 在暂停期照常可用 —— 否则等于把眼睛也蒙上。
- **被拦下的一笔不会写进限流台账**（闸门从前到后短路），"拦了没发"与"发了"不会混在账上。
- `--force` 是急诊出口，**每次越过都会打印一行**（不是静默通道）。一个没有出口的闸门
  会把人赶去绕开 CLI（面板/原生工具），那条路不受任何约束 —— 比不设闸门更糟。
- 闸门只覆盖走 CLI 的通路；面板与原生工具不在其中。

### ①b 回执协议（两段式，成员必读）

| 层 | 名字 | 谁产生 | 会不会多出一条消息 |
|---|---|---|---|
| ① | **接受状态 `📨 已送达`** | 机器，发送那一刻自动成立 | **不会**，面板上只有一个状态点 |
| ② | **正式回执 `--ack` / `--decline`** | **收到 ask 的那个 agent 自己** | 会，它是你自己的话 |

```powershell
# 排队结束、读完任务、动手之前 —— 先回执：
node bin/say.mjs --ack     <那条 ask 的 #短id> --text-file C:\tmp\ack.md
node bin/say.mjs --decline <那条 ask 的 #短id> --text-file C:\tmp\decline.md
```

收件人自动 = 那条 ask 的发起者（不用写 `--to`）；正文必填、必须是你自己的话（接/推 + 计划 + 预计时间）。
`--inbox` 会把没回执的 ask 标成 `⚠️ 欠回执` 并把该敲的命令打出来。详见 `AGENT-GUIDE.md` §1.6。

### ② 原生工具 `studio_say` / `studio_members`（**需重启主星一次**）

每条发出的消息都带一个 **6 位短 id**（消息头里的 `｜#abc123`），用来**精确引用某一条**：
`--reply-to <短id>` 会自动在正文最前带一行引用；短 id 在 `--inbox` 与面板「群聊」页都能看到。

`src/tools.js` 在宿主根上下文注册两个**全局**工具（所有 agent 都能看到）：

| 工具 | 作用 |
|---|---|
| `studio_members` | 列出群成员（显示名 / 角色 / 能力标签 / 会话 id），发消息前先查对方叫什么 |
| `studio_say` | `{to, text, kind?}` —— 把一条群聊消息投递给另一位成员 |

为什么需要重启：宿主插件条目一旦加载就不会重新 import，且 patch 层的**新增行在运行期不会生效**
（实测：加行 + 触碰配置文件都不会重载）。所以这一行要等下一次启动主星才生效。
在那之前用上面的命令行接口，两者走的是同一条通路。

## 群聊与会话视图的**双向隔离**

| 方向 | 行为 |
|---|---|
| 群聊 → 单会话 | 群聊产生的**整个回合**（请求 + 对方回复 + 该回合的工具调用）在单会话视图里**收起**（可在面板关掉这个开关） |
| 单会话 → 群聊 | 会话自己的消息（人手动打的、运行期注入、子代理汇报、它自己干的活）**不进群聊** |

**记忆是同一份**：消息照旧写进各自的会话日志（模型能看见、能接着做），隔离只发生在**显示层**。
单会话侧按会话视图的回合结构（`user` → … → `turn-tail`）整段收起；
群聊侧只记录「带群聊前缀的消息」＋「同一回合里的助手回复」。

## 数据落在哪

| 数据 | 位置 | 说明 |
|---|---|---|
| 成员、群 | `$DSH_HOME/studio/studio.json` | 插件自有，原子写（临时文件 + rename）；坏内容会被宽容修复而不是让插件起不来 |
| 群时间线 | 浏览器 `localStorage['dsh.studio.timeline']` | 最多 200 条、单条 2000 字；换窗口/清缓存就没了 |
| 面板开合与页签 | 浏览器 `localStorage['dsh.studio.ui']` | 纯 UI 偏好 |

**插件从不写**：会话日志、workspace 域（除置顶那一次显式 RPC）、settings、任何别人家的存储。

## 诊断

```js
window.__DSH_STUDIO__              // 不存在 = 插件没加载
window.__DSH_STUDIO__.state        // { open, tab, data:{members,groups,lock}, error, notice, timeline }
window.__DSH_STUDIO__.timeline()   // 群时间线数组
window.__DSH_STUDIO__.refresh()    // 重新拉宿主状态
window.__DSH_STUDIO__.probeArchive('session-…')  // 只读地走一遍被包装的归档方法（验证锁）
```

面板底部常驻显示：数据文件路径、锁定位是否安装、已拦截归档次数与最近一次，
以及 **「界面注入：样式表 N 字符」** —— 侧边栏让位、成员行标记、群聊回合隐藏全部靠注入的样式表；
一旦这行显示 **0 字符或标红**，就是注入失败（会同时显示失败原因），而不是"功能没了"。

## 已知限制

1. **宿主半边改代码不会热重载**。`cordis-plugin-hmr` 只监视 profile 目录（`root` 默认 `["."]`、`ignored` 含 `**/node_modules`），
   而本插件源码在 **profile 目录之外**、经 junction 进入 —— 所以 `src/index.js` 的改动**要重启主星才生效**。
   客户端半边不受影响：宿主会重新读取 bundle，刷新页面即可。
   （正因为这个，S4 的时间线才放在客户端。）
2. **侧边栏置顶只在「手动排序」模式下可见**（视图默认是「最近更新」）。面板会在这种情况下常驻提示。
3. **颜色标签只作用于工作室面板**。要在产品侧边栏给会话上色需要顶掉 `sidebar.workspaces`（single 槽位），本插件不做。
4. **别名不改会话标题**（零侵入）。真改名是另一个显式动作，v1 未实现。
5. **群聊只有手动投递**，没有自动镜像 —— 两个带工具的 LLM 互相触发会 ping-pong，故明确不做。
6. 对端若是 subagent 拥有的会话，宿主会以 `agent-busy` 拒绝（既有 fence），面板显示错误原文。
7. 文案是中文硬编码，未接产品 locale。
8. **侧边栏的成员标记是"外部呈现"，依赖产品 DOM 结构**，但**失败时只会不生效、不会坏**：
   - 会话行没有任何标识属性，所以 sessionId 是从 **React fiber** 里只读取出来的
     （`SessionNodeItem` 的 `props.node.id`）；取不到就不标记，什么都不做。
   - 置顶/灰底/圆点全部靠注入的 `<style>` 与属性选择器（用 `:has()` 与结构定位，不依赖 hashed 类名）。
   - 面板"占位"用的是 `margin-left` 让位 + 面板贴侧边栏右侧；侧边栏宽度是实时测量的。
   - 产品如果改了行结构或包名，表现是"标记消失"（可在成员台用两个开关关掉），不会影响会话功能。
9. **置顶只在所属工作区分组内生效**（不同工作区之间不会跨组移动），且**不改动持久顺序**——
   要写进 workspace 顺序（「手动排序」模式下可见）仍用成员卡上的「同步到侧边栏顶部」按钮。
10. 成员之间的先后顺序沿用侧边栏原有顺序（不按成员台的置顶重排）。
11. **消息优先级队列：代码已写好，等一次重启生效**（需求：人的消息 > 人发起的群聊消息 > 成员发起的群聊消息）。
    查清的现状：`session.prompt` 只有 `queue` / `steer` 两种 mode，GUI 输入框与 CLI **都走 `queue`**，
    落到 `Inbox` 的 `next-turn` 数组里是**严格 FIFO**，没有任何优先级概念 —— 所以"人优先"在 RPC/客户端层做不到。
    实现放在宿主侧 `src/priority.js`（composition 里的 `dsh-studio/priority` 行）：
    监听 `agent/inbox/inserted`，用**全同步**的 `inbox.mutate('next-turn', ...)` 原位重排，
    **只重排、不抢占正在跑的回合、不删除、不重发**；顺序本来就对时不写任何东西。
    - 生效条件：**重启主星一次**（宿主条目不会重新 import，patch 层新增行运行期不生效）。
    - 重启前先跑 `node test/preflight.mjs`（确认三行都能加载，避免起不来）。
    - 关掉：环境变量 `DSH_STUDIO_PRIORITY=0`。
    - 自检：重启后看 `$DSH_HOME/studio/priority.json` 的 `insertsSeen` / `reorders` / `lastReorder`。
12. ⚠️ **产品的会话列表在「折叠」时只渲染前 N 个会话** —— 这是**产品侧写死的常量**，不是本插件的行为：
    `dsh-client-ui-workspace/lib/client.js:1039` `const COLLAPSED_SESSION_LIMIT = 5;`，
    配合 `:1404` 的 `group.sessions.slice(0, COLLAPSED_SESSION_LIMIT)` ⇒ **折叠态只渲染 5 行**，其余收在「展开其余 N 个会话」里。
    - **后果**：本插件的"成员置顶"是**纯 CSS**（给已渲染的行打属性 + flex `order`）——
      **行没被渲染就没有元素可置顶** ⇒ 成员会"看不见"，手动展开后才置顶、收起又没了（实测中报告过）。
    - **一个变通**：若你确实需要折叠时多显示几行，可以改这个产品常量 —— 纯客户端渲染 ⇒ **只需刷新页面**，
      不改协议/数据；DSH 升级会覆盖，改之前先备份。注意那是**改宿主产品**，不是改本插件、也不在本仓库范围内。
    - **开源版怎么办**：这是**产品常量**，插件不该也无法从插件侧改它。
      开源文档应把它写成"已知限制 + 可选补丁"，而不是在插件里塞 hack（比如自动点"展开其余"会改变用户的侧边栏布局）。
    - **可核对的读数**：插件在 `html` 上写了 `data-dsh-studio-anchors`（已标注行数）与
      `data-dsh-studio-unresolved`（没解析出行 id 的数量）——一眼分辨"行没被渲染"与"行没被解析出"。
